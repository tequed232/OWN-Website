# Anthropic / Claude 设计语言与 UI/UX 交互研究

> 用途：为 OWN-Website 建立 Anthropic / Claude 品牌视觉与产品交互的研究参考。  
> 定位：学习其设计原则与交互方法，不复制 Anthropic 的商标、专有资产或完整界面。  
> 说明：本文将官方公开资料、可观察的产品体验与 OWN-Website 的设计推导分开记录。

## 1. 核心概括

Anthropic / Claude 的设计语言可以概括为：

**Editorial Minimalism + Warm Humanism + Conversational UX**  
编辑式极简 + 温暖的人文气质 + 对话式交互。

它的关键并不是“米白色背景加橙色按钮”，而是让内容、排版和交互承担主要表达任务：

- 用清晰的排版层级建立阅读节奏。
- 用温暖但克制的中性色降低工具的冷硬感。
- 用少量强调色标识关键动作和状态。
- 让对话成为工作入口，而不是把用户强迫进复杂表单。
- 通过上下文内编辑、预览和细粒度调整缩短创作反馈循环。

## 2. 品牌视觉语言

### 2.1 色彩系统

Anthropic 官方公开的 brand-guidelines Skill 提供以下品牌色参考：

| Token | 色值 | 参考用途 |
| --- | --- | --- |
| Dark | `#141413` | 主文字、深色表面 |
| Light | `#faf9f5` | 浅色背景、深色背景上的反白 |
| Mid Gray | `#b0aea5` | 次级文字与中性元素 |
| Light Gray | `#e8e6dc` | 柔和分隔与次级表面 |
| Orange | `#d97757` | 主要强调色 |
| Blue | `#6a9bcc` | 次级强调色 |
| Green | `#788c5d` | 次级强调色 |

使用原则：

1. 中性色承担大部分界面面积。
2. 强调色应有明确语义，不要把橙、蓝、绿平均铺满界面。
3. 文字与背景必须满足可访问性对比度要求。
4. 状态色不能只靠颜色区分，还要配合文字、图标或形态。
5. 上述色值是品牌参考，不意味着 OWN-Website 必须原样采用。

### 2.2 字体与排版

Anthropic 官方 brand-guidelines Skill 为文档类品牌化产物提供了 Poppins（标题）与 Lora（正文）的字体搭配，并给出 Arial / Georgia 回退方案。它不应被误读为 Claude 产品 UI 所有页面的完整字体实现规格。

可借鉴的排版方法：

- 标题与正文承担不同的阅读角色。
- 展示性标题可以有更鲜明的字形性格，正文优先考虑长时间阅读的舒适度。
- 通过字号、字重、行高和段落间距建立层级，而不是依赖彩色标签。
- 控制正文行宽，避免桌面端超长行。
- 中文界面需要单独验证 CJK 字体回退、标点挤压、数字与西文混排。

### 2.3 图形与品牌气质

可观察到的品牌表达倾向：

- 有机、自然、非机械化的图形语言。
- 克制的装饰，不让插画或纹理压过信息。
- 温暖的中性色与少量陶土色强调。
- 通过字体和版面建立个性，而不是依赖复杂图标。

不要将 Claude 的标志、星芒图形或品牌插画直接改造为 OWN-Website 标志。

## 3. Claude 产品 UI/UX：值得研究的交互模式

本节关注产品工作流，而不是将营销网站的视觉风格直接套用到应用界面。

### 3.1 对话优先（Conversation-first）

对话是用户表达目标、补充上下文和迭代结果的主要入口。

借鉴建议：

- 输入区应清晰、易发现，并在长页面中保持合理可达性。
- 用户输入、系统状态、工具执行结果和最终产物要有明确区分。
- 让用户能够在原上下文中继续追问，不必反复切换页面。
- 对耗时任务显示可理解的进度与当前阶段，避免只有无意义的 loading 动画。
- 允许用户中断、修改或继续任务。

### 3.2 对话与产物并行（Chat + Artifact）

Claude 产品设计实践中出现了聊天与 HTML 产物并排的工作区模式：左侧进行对话，右侧查看可交互结果。

适合 OWN-Website 的应用：

- 桌面端：对话 / 控制区与预览 / 详情区并排。
- 移动端：切换式或分段式视图，不强行压缩成双栏。
- 产物区应有明确的保存、复制、导出或打开操作。
- 预览区与编辑区共享同一份状态，避免修改后需要手动刷新。
- 用户应能返回此前版本或撤销最近一次编辑。

### 3.3 上下文内修改（Inline Editing）

Claude Design 公布的交互方式包括对具体元素添加评论、直接编辑文字，以及通过调整控件修改布局和样式。

可借鉴：

- 允许用户针对某张卡片、某个模块或某段内容提出修改。
- 将评论锚定到具体对象，而不是要求用户描述“页面右边那个东西”。
- 提供直接编辑与自然语言修改两条路径。
- 对可调整参数提供有边界的滑块、选项或数值输入。
- 修改前后提供清晰反馈；批量修改应能预览影响范围。

### 3.4 状态反馈与可恢复性

交互必须解释系统正在做什么、发生了什么、用户下一步能做什么。

建议统一以下状态：

| 状态 | 界面反馈 | 可用操作 |
| --- | --- | --- |
| Idle | 等待输入或选择 | 开始任务 |
| Queued | 已进入队列 | 查看队列、取消 |
| Running | 展示当前步骤与进度 | 中断、查看详情 |
| Needs input | 明确指出缺少的信息 | 补充信息 |
| Succeeded | 展示结果与产物 | 打开、复制、继续 |
| Failed | 说明失败原因与可行修复方式 | 重试、修改参数 |
| Cancelled | 说明任务已停止 | 重新开始 |

错误信息应该具体说明发生了什么，以及如何恢复。空状态应引导用户完成第一步，而不是只放一张插画。

### 3.5 渐进披露（Progressive Disclosure）

- 默认只展示完成当前任务所需的控件。
- 高级参数放在可展开的设置区域。
- 将危险操作与普通操作分开，并提供确认或撤销机制。
- 详细日志、调试数据和模型参数不应挤占普通用户的主要工作区。

## 4. OWN-Website 的融合方案

OWN-Website 已确定的方向是瑞士国际主义设计与构成主义。建议将三者分工，而不是把不同品牌元素混在一起：

| 来源 | 借鉴内容 | 在 OWN-Website 中的角色 |
| --- | --- | --- |
| Swiss International Style | 网格、对齐、信息层级、留白 | 页面骨架 |
| Constructivism | 几何构图、视觉张力、有限的强调色 | 项目展示与视觉识别 |
| Anthropic / Claude | 温暖中性色、编辑式排版、对话优先、上下文内编辑 | 内容气质与交互方式 |
| OpenAI | 几何抽象、连续结构、人文与技术平衡 | 图形系统与动效研究 |

### 4.1 建议的 OWN-Website 色彩策略

不要直接复制 Anthropic 的完整品牌色板。可以从它的温暖中性色出发，建立 OWN-Website 自己的语义 Token：

| Token | 建议初始值 | 语义 |
| --- | --- | --- |
| `--surface` | `#FAF9F5` | 页面主背景 |
| `--surface-raised` | `#FFFFFF` | 浮层、卡片与编辑面板 |
| `--text-primary` | `#20201E` | 主文字 |
| `--text-secondary` | `#77756F` | 次级文字 |
| `--border-subtle` | `#E8E6DC` | 轻分隔线 |
| `--accent` | 项目自有强调色 | 关键操作与选中状态 |

以上是供原型测试的起始 Token，不是 Anthropic 官方色板，也不是最终定稿。应结合现有网站色彩与项目卡片的动态主题系统验证。

### 4.2 建议的组件行为

| 组件 | 交互要求 |
| --- | --- |
| Project Card | 清晰 hover / focus / selected 状态；移动端点击选中 |
| Detail Panel | 桌面端与卡片并行；移动端使用页面内切换或抽屉 |
| Tarot Card | 保留用户已确定的翻转叙事，但减少无意义循环动画 |
| Social Metrics | 图表可查看具体数值、日期与数据来源 |
| Settings Panel | 支持键盘操作、拖拽与尺寸调整时保留边界 |
| Dialog / Drawer | 明确关闭方式，支持 Esc 与焦点管理 |
| Loading State | 展示实际任务阶段，不使用无限期假进度 |
| Error State | 提供原因、恢复动作和必要的技术详情入口 |

### 4.3 响应式交互原则

- 桌面端优先使用并行信息结构，让用户同时看到对象与详情。
- 手机竖屏采用单列流程；详情通过抽屉、独立视图或自然导航呈现。
- 横屏手机可在空间允许时使用双栏，但必须保证触控目标足够大。
- 动画应尊重 `prefers-reduced-motion`。
- 交互不能只支持 hover；所有关键能力必须可触摸、可键盘访问。

## 5. 动效原则

Anthropic 的公开产品设计资料强调通过对话、评论、直接编辑和可调控件进行迭代。由此推导 OWN-Website 的动效规则：

1. **响应动作：** 用户点击、展开、选择后才触发主要动效。
2. **表达变化：** 动画应说明内容如何出现、移动、选中或保存。
3. **可中断：** 不阻塞用户下一步操作。
4. **短而稳定：** 避免多个组件同时无目的运动。
5. **状态一致：** 动效结束后的状态必须与数据状态一致。
6. **低动态支持：** 减少动态偏好下使用淡入或直接切换等替代方式。

## 6. 可访问性与质量验收

- 正文对比度至少满足 WCAG AA（通常 4.5:1）。
- 大字号文字与必要的非文本 UI 对比度满足相应标准。
- 所有交互控件具有可见键盘焦点。
- 按钮、链接和图标控件具有明确名称。
- 抽屉、弹窗正确管理焦点，关闭后将焦点还给触发控件。
- 错误不能仅通过颜色表达。
- 触控目标尺寸适合移动设备。
- 减少动态效果设置得到尊重。
- 空状态、加载、失败、取消、成功状态均经过测试。

## 7. 交给 Agent 的实施约束

如果后续将本文用于 OWN-Website 的 UI 重构：

1. 先检查现有组件、Token、路由和响应式断点，不要先替换整个设计系统。
2. 不改变社交媒体数据接入与现有业务逻辑，除非任务明确要求。
3. 先提交设计 Token 与关键组件方案，再实施页面级变更。
4. 每个交互必须覆盖 idle、hover、focus、active、disabled、loading、error 等适用状态。
5. 桌面、手机竖屏、手机横屏分别验收。
6. 运行现有测试、类型检查、构建与无障碍检查。
7. 提交 PR，列出变更范围、截图、测试结果和未解决问题。
8. 不以“看起来像 Claude”为验收标准；以可读性、可用性、一致性和品牌独立性为标准。
